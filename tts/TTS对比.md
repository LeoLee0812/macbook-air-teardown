# 旁白 TTS 对比：qwen-audio-3.1-tts-next vs flash

同一套 22 段文案、同一个音色（`longsanshu_v3.1`，沉稳男声），分别交给两个模型合成，排进同一条成片时间轴。

## 结论

- **Next 语速快、语流连贯、语调更平稳**，22 段全部不用提速就塞进了画面节奏；但接口和稳定性都更难伺候：要念的字得放进 `text_prompt`、句首常吞字或多出一个字，5 段要多录几条才挑出干净的，合成一段要 12–17 秒。
- **Flash 开箱就准、快约 15 倍**（一段约 1 秒），但说得慢、句中停顿多，有 5 段要提速到最多 1.15 倍、2 段还是比画面晚了一点；音高起伏比 Next 大（基频波动 5.8 对 3.7 个半音）。
- 两版最终的转写准确率都很高（剩下的差异基本是「铰链/脚链」这种同音字，是识别器的问题）。**听感好坏我没法替你下结论**——我听不了音频，Gemini 盲评这次也因为中转丢音频没跑成，建议你直接对着两个成片 A/B 听一遍。

## 踩过的坑

1. **Next 的字段是反的**：要念的字放 `input.text_prompt`（必填），`input.text` 是风格描述。把描述放进 text_prompt，它会念一句自己编的试听句（「科技正在重塑我们理解世界的方式」）。
2. **Next 句首吞字**：「没有风扇」被念成「有风扇」，意思全反；文本前面加一个「，」就好了。个别句子还会多出一个字（「空，松开铰链」），换成「。」开头、多录几条挑出来。
3. **风格描述会让 Next 改字**：在 text 里写「沉稳、像纪录片解说」后，它会漏掉短语、换词，最后两版都不写风格描述，只靠音色。
4. **「MagSafe」两个模型都读不准**（读成「马克西弗」「make safe」），旁白改成「充电口也是」，屏幕标注照样写 MagSafe 3。
5. 为了照顾 Next，有 3 句换了说法（「把它翻过来…」「充电口也是」「松开铰链，屏幕就能取下」），两版用的是改完后的同一份文案。
6. Flash 的音色 ID 要用拼音（`longsanshu_v3.1`），文档里的中文名 ID 会报引擎错误。
